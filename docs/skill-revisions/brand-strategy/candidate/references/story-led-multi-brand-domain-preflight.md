# Story-led multi-brand naming and `.com` preflight

Use when one founder is naming separate organizations (for example a game company and an open-source organization) and wants names that are both story-rich and domain-viable.

## Correct framing

- Do not force one umbrella name across organizations with different audiences and promises.
- Define a separate emotional job for each brand. Example: games = wonder, motion, delight; OSS = contribution, stewardship, shared infrastructure.
- A founder trait should inform the story without becoming a literal translation such as `Happy`, `Smile`, or a surname-plus-generic suffix.

## Name-quality gate

A candidate must carry all four:

1. **Plain-language comprehension:** understandable on first encounter.
2. **Story seed:** a one-sentence founding narrative.
3. **Design seed:** at least one credible logo, motion, or visual-system direction.
4. **Portfolio room:** not tied to one genre, product, or current technology.

Names such as `Windward` or `Daystar` illustrate the target shape: familiar components, evocative but concrete, visually generative, and usable in prose. Avoid fantasy vowel strings, arbitrary suffixes, and mechanically generated forms that exist only because a domain is free.

## Domain contract must be explicit

Before generating at scale, settle the exact rule:

- preferred: exact `brand.com`;
- optional category fallback only if the user allows it, such as `brandgames.com` for a gaming company;
- do not silently substitute `brandcode.com`, `getbrand.com`, `.dev`, `.org`, or another pattern.

If the user wants 40–50 candidates with verified domains, domain-check the internal pool before presentation, but never let availability override pronounceability, comprehension, story, or visual identity. Return fewer names and explain the trade-off rather than padding with malformed names.

## Availability evidence

Use `references/domain-constrained-brand-longlists.md` → Registration-evidence procedure. Preserve the exact domain, authoritative source, check time and uncertainty. RDAP/WHOIS from the same registry are not independent evidence; DNS silence is not non-registration. Registrar availability, legal clearance and purchase remain separate.

## Longlist-to-finalist sequence

1. Generate a broad internal pool for each brand independently.
2. Apply comprehension, story, visual, pronunciation, and portfolio gates.
3. Apply the user-approved domain pattern exactly.
4. Present a domain-verified longlist only if explicitly requested.
5. Ask the human to select a generous reaction set (for example 5–10 per brand), not finalists immediately.
6. Deep-check the reduced set across exact web, adjacent companies/products, GitHub, packages, social surfaces, and preliminary trademark sources.
7. Score and present finalists at the requested scale; do not force three per brand.
8. Purchase/registration remains a separate spending approval.

## Failure pattern to avoid

Do not react to scarce exact `.com` inventory by appending random endings (`-ik`, `-el`, `-en`) to semantic roots and presenting them as brands. A technically free domain attached to an implausible word is not a successful naming result.
